这是一个面向县域治理的**开源决策模拟演示项目（Demo）**，以广东省惠州市**龙门县**为样本。龙门是大湾区北部的生态屏障与旅游目的地，一年涌进约 900 万人次游客，又在平陵布局功能膜新材料。项目把这些真实公开线索组织成“山—水—产业—人”的耦合网络，通过感知、建构、盘点、推演、压测与反思，尝试回答一个朴素的问题：

**一座常住人口仅 35 万、年游客量却约 25 倍于人口的山城，靠什么留住人、留住消费？如果某个变量变了，又会怎样？**

- 在线体验（GitHub Pages）：<https://zhanglingshare.github.io/longmen-simulator/>
- 类型：可直接在浏览器运行的网页（HTML + CSS + JavaScript + ECharts）
- 费用：完全免费，无需注册、无需安装、无需联网授权

## 一、它是什么，不是什么

**它是：**
- 一台把“不确定性”整理成“可看清、可核对结构”的思维工具；
- 一次在公开数据与明确假设之下，对县域未来进行的**压力测试**；
- 一种“先推演、后决策”工作方式的具体示范。

**它不是：**
- 不是对未来的精确预测，不预测具体产值或招商成败；
- 不是因果神谕，不轻易使用“因为 A 所以 B”；
- 不构成任何投资建议，也不替代官方决策。

风洞不替人做决定，它只负责把“看不见的未来”，提前跑给你看。

## 三、核心观点（Demo 版的几点提示）

1. 龙门更像“**流动人口经济**”：年接待游客约 905 万人次，约为全县常住人口（35.31 万）的 **25 倍**；日均外来人次约为常住人口的 7%。
2. “**一张床**”是最值得追问的命题：游客人次在涨，人均消费却略降（混合客单价约 477 元、同比约 −1.75%）；永汉游客 +9.21%、旅游收入仅 +1.25%、客单价约 −7.29%，新增客流里低价一日游占比偏高。
3. 但“一张床”目前是**待验证的核心假设**：县级公开数据中尚无过夜人次、住宿率与平均停留天数，不能仅凭客单价下降就直接推断住宿减少；需补过夜数据，或以永汉剪刀差、床位数/游客量比值作为代理。
4. 工业的弹性在**功能膜新材料**：68 宗项目、约 140 亿投资、620 条涂布线；2026 年规上工业目标 150 亿，需一年增约 25.5%（2025 年实际增 5.1%），达产节奏是关键变量。
5. 好东西的“**变现通道**”普遍还需补强：龙门农民画拿过 41 个国家级奖项、走进奥运与世博，目前更多靠冰箱贴等小件走量——“面子大、里子待补”，与如何把生态与文化资源变成经营者收入是同一道题。

> 以上均为“结构提示 / 关联 / 同步变化”，不是因果断言，更不是定论。

## 四、数据来源与分级

本项目数据**全部来自公开渠道**，并按可信度分为四级，报告中可逐项追溯：

- **A · 实测**：统计公报、政府工作报告、计划执行报告、民生实事中直接给出的数字；
- **B · 推估**：部分历史序列按公开增速回推；
- **C · 代理**：镇街级供给代理（如床位数/游客量比值、人口密度、是否点名），非逐镇街实查；
- **D · 假设**：网络边权重、路径贡献区间、过夜率等（例如缺少真实过夜 OD 数据）。

主要公开来源包括：龙门县人民政府门户网站、统计公报与计划执行报告、文旅与农业公开信息、南方+/惠州日报等媒体，以及微博/抖音/头条等公开热榜。

**数据时效性说明：** 2025 年数据为快报或公报口径，2026 年统计公报发布后部分数字可能微调。今日话题与各镇页**不展示平台后台真实阅读、转发、点赞与“想去”人数**（公开渠道无法获得），改用“关注档（高/较高/中）”与“人气档（高/较高/中）”，并标注数据更新时间。

我们坚持：**可以讨论参数，但不能杜撰数据**；看到一个数字，应能知道它究竟是事实、推估，还是假设。

## 五、模型边界（请务必阅读）

1. **不是预测器**：只在一组公开数据与明确假设下给出叙事分布与结构提示；
2. **不做因果断言**：单一地区、有限时间序列的汇总数据，不足以支撑严格因果结论；
3. **反事实不可验证，但参数可核对**：“通道断了会怎样”无法重演，但每个参数都能回到公开资料核对；
4. **网络为作者据公开主体构建**，边权重含假设，不等同于真实交易或客流数据；
5. **不构成投资建议**，亦不替代任何官方决策，结论随假设改变而改变。

特别说明：风洞页的“盘山通道中断”按**脉冲冲击＋恢复曲线**建模——中断只在冲击发生的那一年一次性作用，之后各年回到正常趋势；这与中心城区“日常性拥堵、每步慢性失血”的压测性质不同，不做简单类比。

## 六、技术细节与可复现性

- 全部为静态 HTML + 原生 JavaScript + ECharts，无后端、无数据库；统一计算内核集中在 `model.js`，未来、风洞、报告与五条路页面共用同一套口径。
- 随机数使用 **mulberry32 固定种子伪随机生成器**：相同种子、相同参数、相同次数必复现同一结果；默认种子 42，可自行修改以检验稳健性。
- 五条路径均以均值 μ 与波动 σ 描述，叠加加性全局噪声；五条路的贡献用**同种子成对对照**（仅关闭该条，比较中位数差）得到，**不把五个数字直接相加，也不把覆盖率当作完成率**。
- 数据血统 A/B/C/D 分级，网络主体与关系可溯源；农产品按当月真实时令切换，非当季品类不出现，播种/育苗品类单独标注、不计为上市。

## 七、为什么做这件事

县域的每一个重大决策，最终都落在具体的人身上——永汉开温泉民宿的、南昆山养蜂种灵芝的、过年走那条雨季易塌方山路回家的。投进去的是真金白银，一旦走偏，代价不小，也很难回头。

这与国家方向一致：“十四五”规划与 2035 年远景目标提出“**加快构建数字技术辅助政府决策机制**”“**探索建设数字孪生城市**”，《数字中国建设整体布局规划》也要求发展高效协同的数字政务；在世界范围内，新加坡（Virtual Singapore）、日本（Project PLATEAU）、英国（What Works Centre）等也在区域决策中采用“先算后干”的方法。这个小小的 Demo，是把上述理念落到一座山城的、具体而微的一次尝试。

## 数据治理与质量门（v2）

### 每日数据（hot.json / life.json）— v2 审计字段

每日雷达（daily-hot-radar / life-pulse-radar）生成的数据文件自 v2 起携带审计字段：

- 顶层：`schema_version: 2`、`updated`（内容时间）、`fetched_at`（快照生成时间）
- 条目级：`published_at`（报道发布时间，未知为 null）、`fetched_at`、`verified_status: "pending"`（待人工核验）

原则与模型口径一致：**不杜撰**（每条话题必须有真实可访问的 `url`/`source`）、**估算必标注**（关注档/热度非平台后台真实统计）。

### 发布前质量门（tests/verify_all.js）

本地或 CI 运行 `node tests/verify_all.js`，全过才允许发布：

1. 全部页面内联 script 语法检查
2. 模型口径断言（SEED=42、N=10000 复算 p10/p50/p90/hit，与页面口径同源，可复现）
3. 每日数据文件 v2 字段校验
4. 事件证据库（evidence/events/*.json）字段完整性

### 事件证据库（evidence/）

"新闻/事件 → 模型参数"必须经过人工审核：雷达只登记事实（`status: pending`、`parameter_change: null`），
审核通过（`status: approved` 且填写 `parameter_change` + `review`）后才由
`node tests/release_params.js` 发布为 `params.json` 参数版本。详见 `evidence/README.md`。

### CI（.github/workflows/verify.yml）

GitHub Actions 在 push/PR 时自动运行质量门。
